The idea that clicked most was waiting for JavaScript on the Canal Street scraper. Nothing is in the HTML until you choose a shop and click "Show full menu", and the cards are drawn by JavaScript after a delay. query_selector_all does not wait, so called too early it returns an empty list with no error. wait_for_selector after the click fixed that, and wait_for_function to check that the card count grew after each "Show more" click made the pagination loop reliable. The second half was crawling: I collected every href with get_attribute first and only then visited each item page with urljoin, because leaving the page throws away the cards you are looping over. I also noticed how different the three techniques were: the ~ sibling selector for Lakeshore's heading-then-grid layout, read_html plus melt for Hilltop's tables (one column per size turned into one row per size), and driving the page like a person for Canal Street.

What confused me was a number that did not match. The README says Lakeshore has 37 rows, but my scraper returned 26 while the tests still passed. I checked the HTML and found 15 menu-card elements (my first grep counted the article and its inner div, which doubled it): 11 drinks at two sizes plus 4 food items is 26. The README's own total of 144 rows only works with 26, so 37 was a typo. The lesson is that passing tests do not prove a count is right, so I should check a scraper's output against the source HTML.

Fuzzy matching also surprised me, because a score measures spelling, not meaning. "Matcha Latte" scores 87 against "Mocha Latte" but is a different drink, and "PSL" scores 18 against "Pumpkin Spice Latte" but is the same one. No threshold gets both right. Normalization (dropping accents, punctuation and filler words) plus an AUTO_MATCH threshold of 90 handles the easy cases, and a human in the loop decides the rest. The owner's saved decisions always win, so the code never asks the same question twice. That design made the analysis trustworthy: my results (25 prices below the market, 10 above, 8 items only the rivals sell, 3 only we sell) matched the expected numbers.

I am still unsure how to choose the threshold for a new dataset. I picked up AUTO_MATCH = 90 and REVIEW = 70 from the assignment without testing other values, so I do not know how many wrong auto-matches a lower threshold would cause.
